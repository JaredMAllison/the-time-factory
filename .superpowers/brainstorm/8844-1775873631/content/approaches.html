TTF 1.0 — Godot 4 Scene Architecture

How should the frontend be structured? Three approaches with tradeoffs.

A

Monolithic Scene

One Main.tscn containing all nodes directly — belt, balloons, panels. Everything lives in a single scene tree.

Pros

  • Fastest to start
  • No scene boundaries to learn yet

Cons

  • Doesn't teach instancing — the key GDScript skill
  • Balloons are hardcoded, not dynamically instanced
  • Swappable balloon assets become a hack
  • Becomes unmanageable fast

Not recommended — defeats the learning goal

B

Component Scenes — Recommended

Each visual unit is its own .tscn file. Main.tscn instances them. Balloons are dynamically instanced from BalloonEvent.tscn at runtime — one per event.

Main.tscn
├── Belt.tscn          ← timeline, scroll, zones
│   └── BalloonEvent.tscn  ← instanced per event
├── HUD.tscn          ← date header, nav
├── EventForm.tscn    ← create/edit panel
├── EventDetail.tscn  ← info panel
└── ApiClient.tscn    ← HTTP request manager

Pros

  • Teaches instancing directly
  • Signals between scenes (core GDScript)
  • Swappable assets slot in cleanly
  • Godot-idiomatic — what tutorials teach
  • Each scene testable in isolation

Cons

  • More files upfront
  • Must understand instancing before starting
C

Layer-Based Architecture

Scenes organized by visual layer responsibility: World (belt, background), Events (balloon container), UI (panels, HUD). Maps to Godot's Z-ordering system.

Main.tscn
├── WorldLayer.tscn  ← belt, background
├── EventLayer.tscn  ← all balloons live here
└── UILayer.tscn    ← panels, HUD, input

Pros

  • Clean visual layering
  • Easy to reason about draw order

Cons

  • Artificial grouping — layers aren't components
  • Signals cross layer boundaries awkwardly
  • Doesn't match how Godot tutorials teach scene composition
